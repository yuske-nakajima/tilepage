# v0.4 columns variant API 設計文書

`supportedColumns` + `breakpoints` による段数 N の離散スナップと、 obstacle 側の `whenColumns` variant 宣言の仕様。横書き (`horizontal-tb`) のみが対象。縦書き (`vertical-rl`) は別 PR で扱い、本 API のスコープ外とする。

`docs/design/v0.4-flow-engine.md` を前提とし、その公開 API (`ColumnsConfig`, `addObstacle`) を後方互換に拡張する。

---

## ColumnsConfig Union 拡張

`ColumnsConfig` は既存 2 モードを保ったまま第 3 モードを足した排他的 Union とする。判別キー (`number` リテラル / `width` プロパティ / `supported` プロパティ) で 3 モードを区別する。

```ts
type ColumnsConfig =
  // 固定 N。 N の値そのまま。
  | number
  // 段幅宣言。 viewport から CSS auto-fit 相当で N を実数導出する。
  | { width: string; max?: string }
  // 離散スナップ。著者が許可した N の集合と、 N ごとの min-width 閾値を渡す。
  | { supported: number[]; breakpoints: Record<number, string> };
```

判別ルール:

| 入力 | モード |
|------|--------|
| `typeof config === 'number'` | 固定 N |
| `'supported' in config` | 離散スナップ (本 PR の新モード) |
| `'width' in config` | 段幅宣言 |

`supported` と `width` を同時に渡すのは型レベルで禁止 (Union が排他)。

`breakpoints` の値は CSS 長さリテラル (`'40em'`, `'90em'`, `'0'` 等)。 `0` は「常に true となる下限」を表す sentinel。 `breakpoints` のキーは `supported` に必ず含まれる N でなければならない (含まれない N は configuration error 扱い、設計上は `supported` の集合がソースオブトゥルース)。

## supportedColumns + breakpoints の N 解決アルゴリズム

「viewport の inline-size がしきい値以上を満たす中で最大の N」を選ぶ。 CSS の `@media (min-width: ...)` を降順に評価したのと同じ意味論。 該当なしの場合は `supported` の最小値にフォールバック (下スナップ)。

擬似コード:

```ts
function resolveN(
  inlineSize: number,                    // 実測 px
  supported: number[],                   // [2, 4, 6, 8]
  breakpoints: Record<number, string>,   // { 8: '90em', 6: '60em', 4: '40em', 2: '0' }
): number {
  // breakpoints の値を px に解決
  const thresholds: Array<{ n: number; px: number }> =
    supported.map((n) => ({
      n,
      px: resolveCssLengthToPx(breakpoints[n]),
    }));

  // viewport >= threshold を満たすうち最大の N
  // (threshold が大きいほど大きい N を要求する想定)
  const matched = thresholds
    .filter(({ px }) => inlineSize >= px)
    .sort((a, b) => b.n - a.n);

  if (matched.length > 0) {
    return matched[0].n;
  }

  // どれも満たさない場合は下スナップで supported の最小値
  return Math.min(...supported);
}
```

例: `supported: [2, 4, 6, 8]`, `breakpoints: { 8: '90em', 6: '60em', 4: '40em', 2: '0' }`。 1em = 16px と仮定して px 換算。

| viewport (px) | N=8 (>= 1440) | N=6 (>= 960) | N=4 (>= 640) | N=2 (>= 0) | 結果 N |
|---------------|---------------|--------------|--------------|------------|--------|
| 320           | ×             | ×            | ×            | ◯          | 2      |
| 640           | ×             | ×            | ◯            | ◯          | 4      |
| 1024          | ×             | ◯            | ◯            | ◯          | 6      |
| 1440          | ◯             | ◯            | ◯            | ◯          | 8      |
| 2000          | ◯             | ◯            | ◯            | ◯          | 8      |

resize で inline-size が境界をまたいだ時のみ N が変わる。 connected な実数導出 (width モード) と異なり、 N は `supported` 内の値しか取らない。

下スナップ default の根拠: 著者が `breakpoints[最小 N]: '0'` を書き忘れた場合でも、 viewport が極端に狭い時に segment 数 0 で死なないように。 `0` を明示的に書くべきだが、 fallback として最小値スナップを保証する。

## whenColumns variant スキーマ

obstacle ごとに「現在の N が X の時、 page=p の col=c, line=l から cols×lines を占有する」という variant を辞書で宣言する。 N キーは `supported` の値と一致するものを採用。

```ts
type WhenColumnsVariant = {
  // 1-indexed のページ番号。 1 が最初のページ。
  page: number;
  // 起点 (1-indexed)。 col=1 が inline 軸の最も start 側、 line=1 が block 軸の最も start 側 (天井直下)。
  at: { col: number; line: number };
  // 占有列数 (inline 軸方向)。 grid-column span 値。
  cols: number;
  // 占有行数 (block 軸方向、行高単位)。 grid-row span 値。 省略時は aspect / 画像 natural aspect から導出。
  lines?: number;
  // セル全体のアスペクト比 'W/H' (例: '3/4', '16/9')。 cols × columnWidth から lines が計算される。
  // lines と同時指定時は aspect 優先 + warn。 パース失敗時は warn して未指定扱い。
  aspect?: string;
  // grid cell の inline 軸 (cols × col-width) に対する画像の幅比率 (0 < x <= 1)。 default 1。
  // 1 未満で部分幅となり、 残った inline 空間に text が回り込む。 範囲外は clamp。
  inlineSize?: number;
  // 部分幅時の inline 軸方向の配置。 default 'inline-start'。
  // horizontal-tb では 'inline-start' = 左、 'inline-end' = 右。
  align?: 'inline-start' | 'inline-end';
};

interface ObstacleOptions {
  shape: ObstacleShape;
  // 現在 N に対する variant 辞書。 N キーが現在 N と一致するものが採用される。
  whenColumns?: Record<number, WhenColumnsVariant>;
  // 既存 API (whenColumns と排他)。
  at?: { col: string | number | [number, number]; row: string | number | [number, number] };
  syncClipPath?: boolean;
}
```

### 索引の意味 (1-indexed)

- `col=1`: その page の段組み inline 軸 start 端の段
- `col=N`: inline 軸 end 端の段
- `line=1`: 段の天井直下 (block 軸の start 端、 horizontal-tb なら最上行)
- `line=k`: 天井から k 行目

### lines / aspect 解決アルゴリズム

`lines` と `aspect` は次の優先順位で行数を決定する。 セル幅は `cellWidth = cols * columnWidth + (cols - 1) * gutter` で計算する (columnWidth / gutter は flow-layer 実測 px)。

1. `aspect` 指定あり (パース成功) → `lines = round(cellWidth * H / W / lineHeight)` で導出。 `lines` も指定されていれば warn を出して `aspect` を採用する。
2. `aspect` 未指定で `lines` 指定 → そのまま採用 (既存挙動の保持)。
3. 両方未指定 → 画像要素なら `naturalWidth / naturalHeight` を W/H として導出。 画像未ロード時は load イベントで再解決する。
4. 上記いずれにも該当しない (画像でない / 画像取得失敗) → フォールバック (`lines = 4`)。

`aspect` のフォーマットは `'W/H'` (例: `'3/4'`, `'16/9'`, `'1.5/1'`)。 W, H は正の数値文字列。 パース失敗時は warn して未指定扱い。

px はライブラリ内に長さリテラルとして書かない (評価軸 #4)。 計測は CSS 変数 (`--tilepage-gutter`, `--tilepage-line-height`) と要素 `clientWidth / clientHeight` 経由で行う。

#### 計算例

| cols | columnWidth | gutter | lineHeight | aspect | cellWidth | cellHeight | lines |
|------|-------------|--------|------------|--------|-----------|------------|-------|
| 2    | 100         | 10     | 20         | 3/2    | 210       | 140        | 7     |
| 2    | 100         | 10     | 20         | 3/4    | 210       | 280        | 14    |
| 3    | 100         | 10     | 20         | 16/9   | 320       | 180        | 9     |

CSS Grid の line index と整合する (1-indexed)。 `grid-column: col / span cols`, `grid-row: line / span lines` にそのまま流し込める。

### inlineSize / align による部分幅配置 (N=1 雑誌的配置)

`inlineSize` (0 < x ≤ 1) は grid cell の inline 軸に対する画像幅の比率。 1 未満で grid cell 内に空間が残り、 そこに text が inline 軸方向で回り込む。 `align` は部分幅時の inline 軸方向の配置 (`'inline-start'` / `'inline-end'`、 default `'inline-start'`)。

`attachVariantObstacle` は variant から CSS 変数 `--tilepage-obs-inline-size` (%) と `--tilepage-obs-justify` (`start` / `end`) を obstacle 要素に書き込む。 CSS 側は `inline-size: var(--tilepage-obs-inline-size, 100%)` + `justify-self: var(--tilepage-obs-justify, stretch)` で受ける。

`reflowObstacles` は obstacle に部分幅が指定されている場合 (`inlineSize < 1`)、 float の `inline-size` を obstacle 自身の inline 軸寸法に揃え、 `align: 'inline-end'` なら float-side を `'right'` に切替える。 全幅 (default) では従来通り column 全幅 float のままで shape-outside だけが obstacle 形状を表現する。

| 変種 | inlineSize | align | float-side (horizontal-tb) | text 回り込み方向 |
|------|------------|-------|----------------------------|-------------------|
| 全幅 (default) | 1 | 'inline-start' | left | block 軸方向 (下) のみ |
| 左寄せ部分幅 | < 1 | 'inline-start' | left | inline 軸 (右) に流れる |
| 右寄せ部分幅 | < 1 | 'inline-end' | right | inline 軸 (左) に流れる |

N=1 雑誌的配置の例:

```
horizontal-tb / N=1 / page 1
inline 軸 (横) →

inlineSize=1 (全幅, line 1-12)
┌──────────────────────────────┐
│ img full-width               │
│ img full-width               │
└──────────────────────────────┘
text text text text text text   ← line 13 以降

inlineSize=0.5 align='inline-end' (line 12-)
text text text text │ img right│
text text text text │ img right│
text text text text │ img right│
└──────── flow ─────┴── float ─┘
```

vertical-rl は本仕様のスコープ外 (axis swap が未整備のため warn のみ)。

### legacy `at` との排他

`whenColumns` と `at` は同時指定不可。 同時指定された場合は `whenColumns` を優先し、 `at` は無視する (型レベルでは排他にならないため runtime guard で潰す)。 既存 demo / e2e は `at` のみ使用するため非破壊。

## graceful degradation 戦略

未定義 N の variant を持つ obstacle は、 その N の間 **`display: none`** で隠す。 DOM は残し、 N が変化したら復活させる。 警告もエラーも出さない。

### 設計判断

| 観点 | 採用 (display:none) | 不採用案 (warn / DOM 削除) |
|------|---------------------|---------------------------|
| HTML 哲学との整合 | ◯ unknown 要素を無視するのと同じ | × HTML は警告を吐かない |
| reflow 復活 | ◯ N が戻れば即表示 | × DOM 再生成コスト |
| 雑誌組版的妥当性 | ◯ 「この紙面では省略」が自然な編集判断 | × |
| visible text 照合 | ◯ `display: none` は visible 判定に含まれない | △ |
| 著者の気付き | × silent | ◯ |

著者の気付きは demo / E2E / DevTools (`data-when-columns` 属性) で代替する (後述「属性規約」)。 production 挙動としては silent degrade。

### 部分宣言時の挙動例

```ts
// 著者宣言: N=4 と N=6 にだけ variant を書いた obstacle
addObstacle(book, {
  shape: 'rect',
  whenColumns: {
    4: { page: 1, at: { col: 1, line: 1 }, cols: 2, lines: 4 },
    6: { page: 1, at: { col: 1, line: 1 }, cols: 2, lines: 6 },
    // 2 / 8 は未宣言
  },
});
```

各 viewport での挙動:

| 解決 N | obstacle 挙動 |
|--------|---------------|
| 2      | `display: none` (DOM 存在、 非表示) |
| 4      | 表示、 `whenColumns[4]` の配置 |
| 6      | 表示、 `whenColumns[6]` の配置 |
| 8      | `display: none` |

resize で N が `2 → 4 → 6 → 8 → 6` と動いても、 each cycle で `resolveVariant(obstacle, N)` を再評価し `display` を切り替える。 obstacle の polygon clip / float 注入も `display: none` 時は計算スキップする (cost 削減と V === S 担保のため)。

## line 単位 y 座標の CSS 表現

obstacle-layer に「行高グリッド」を導入する。 CSS Grid の `grid-template-rows: repeat(auto-fill, var(--tilepage-line-height))` で N とは独立に **block 軸方向に行高ピッチで line を切る**。 obstacle の y 座標は line index (整数) で表現でき、 px が一切介在しない。

### CSS 構造 (擬似)

```css
.tilepage-obstacle-layer {
  display: grid;
  grid-template-columns: repeat(var(--tilepage-columns), 1fr);
  grid-template-rows: repeat(auto-fill, var(--tilepage-line-height));
  inline-size: 100%;
  block-size: 100%;
}

.tilepage-obstacle {
  /* whenColumns 解決時に JS から付与 */
  grid-column: var(--obs-col) / span var(--obs-cols);
  grid-row: var(--obs-line) / span var(--obs-lines);
}
```

### `--tilepage-line-height` の供給

flow-text の `line-height` を JS で実測し、 book root に `setProperty` する。

```ts
// 擬似コード (sprint 4 で src/flow/measure.ts に追加)
function measureLineHeight(book: Book): number {
  // 1. flow-text の 1 文字 range を取り、その block 軸サイズを得る
  const sampleColumn = book.pages[0].flowLayer.querySelector('.tilepage-column');
  const textNode = findFirstTextNode(sampleColumn);
  const range = document.createRange();
  range.setStart(textNode, 0);
  range.setEnd(textNode, 1);
  const rect = range.getBoundingClientRect();
  const lh = projection.blockAxisOf(rect).size;

  // 2. NaN / 0 ガード (フォント未ロード等)
  if (!Number.isFinite(lh) || lh <= 0) {
    return fallbackEmPx(book); // 1.5em 相当の概算
  }
  return lh;
}

// reflow cycle 内で root に流す (CSS 変数経由)
book.root.style.setProperty('--tilepage-line-height', `${measureLineHeight(book)}px`);
```

`--tilepage-line-height` の値は実測 px だが、 これは **CSS 変数の中に隠蔽された測定結果** であり、 アプリケーション側 CSS ファイルや公開 API には px リテラルは現れない (評価軸 #4)。 ロジック内で文字列リテラル `${n}px` を書くのは CSS 変数への setProperty 呼び出し 1 箇所だけ。

### 実装方針

- obstacle-layer の `grid-template-rows` は `auto-fill` で page の block-size 全体を line で埋める
- obstacle が `whenColumns[N].at.line` を CSS Grid `grid-row-start` にそのまま渡す
- ページをまたぐ variant (`page` 指定が page 数を超える) は graceful degradation 対象として `display: none`
- フォント読み込み完了を待ってから初回 reflow を走らせる (`document.fonts.ready` await)

## 属性規約

JS 側が DOM に同期する属性を仕様として固定する。 E2E / Sprint 2 RED test と Sprint 3/4 実装が同じ属性名で会話するための約束。

| 属性 | 付与先 | 値 | 同期タイミング |
|------|--------|-----|----------------|
| `data-active-columns` | book root (`.tilepage-book`) | 現在の N の数値文字列 (`"6"` 等) | 毎 reflow cycle で書き換え |
| `data-when-columns` | 各 obstacle 要素 | 現在 N で適用された variant のキー (`"6"`)。 graceful degradation 時は `""` または属性削除 | 毎 reflow cycle で resolveVariant 後に書き換え |

DevTools で「今この obstacle はどの variant で配置されているか」を目視できる。 E2E でも `page.locator('[data-active-columns="6"]')` のような selector で N を assertion できる。

`data-when-columns=""` (空文字) と「属性なし」のどちらを degrade 状態の表現とするかは Sprint 4 実装で決める。 Sprint 2 の E2E は両方を許容するように書く (`not.toHaveAttribute` か `toHaveAttribute('', '')` のどちらかで pass)。

## 評価軸 6 項目との mapping

`plans/2026-05-14_v0.4-evaluation-criteria.md` の 6 項目に対して本 API がどう作用するかの一覧。

| 評価軸 | 項目 | 本 API での扱い |
|--------|------|-----------------|
| #1 | text は 1 本の連続ストリーム、 page は可変、 resize で再分配 | 維持。 obstacle の N 変化時は variant resolve のみ走り、 stream 自体は flow engine が従来通り再分配する。 `whenColumns` 切り替えで page 数も flow 側の判断で増減 |
| #2 | 横書きも縦書きも同じ flow engine、 duplicate 設計は両方捨てる | 維持。 本 PR は horizontal-tb のみだが、 line グリッドの軸算出も axis projection を経由するため将来 vertical-rl 対応時に同じ engine で機能拡張可能 |
| #3 | 段数は N (configurable)、 6 はデフォルト値に過ぎない | **強化**。 連続的な N 導出 (width モード) に加えて、 著者が許可した離散 N にスナップするモードが追加され、 N の取りうる値を著者が一級で制御できるようになる |
| #4 | px 固定なし、 論理プロパティ + 1fr / % で軸抽象化 | **強化**。 obstacle y 座標が grid-row のセル番号から line 単位 (行高ベース) に拡張される。 行高は CSS 変数 `--tilepage-line-height` 経由で配られ、 アプリ側 CSS にも公開 API にも px リテラルは現れない |
| #5 | 検証は visible text 文字数照合 (DOM 存在ベースは不可) | 維持。 graceful degradation は `display: none` を使うため `visibleTextOf` が emit しない。 `V === SOURCE_TEXT` は引き続き成立する |
| #6 | CSS でできないところは JS で測って切る | 維持・拡張。 `measureLineHeight` を `src/flow/measure.ts` に追加し、 Range API + getClientRects で行高を実測する。 N 解決の breakpoint px 換算も JS で行う |

評価軸 #3 / #4 は本 API の存在意義そのもの。 #1 / #2 / #5 / #6 は既存設計を壊さないことが要件。

## スコープ宣言: horizontal-tb のみ

本 API (`supportedColumns` / `breakpoints` / `whenColumns`) は writing-mode `horizontal-tb` を対象とする。 縦書き (`vertical-rl`) は別 PR で扱う。 理由:

- 縦書きでの line グリッドは inline 軸 (縦) 方向の文字面サイズ + block 軸 (横) 方向の行ピッチで定義が swap される。 同じ projection の延長で実装可能だが、 E2E の 4 viewport sweep を縦書きと共有すると assertion が複雑化する
- 横書きの離散 N スナップが先に固まる方が後の縦書き拡張で互換性問題を避けやすい

縦書き対応時にも:

- `supportedColumns` / `breakpoints` の意味論は変わらない (inline-size の解釈は projection 経由)
- `whenColumns` の `at.col` / `at.line` は inline 軸 / block 軸の論理座標なので、 縦書きに自然に拡張できる

縦書きで本 API を有効化するのは別 PR の判断とし、 本 PR では `writingMode === 'vertical-rl'` のとき `supportedColumns` 指定はエラーとして扱う (実装方針: createBook で early throw)。

|----------|---------------|
| `createBook({ columns: 6 })` (固定 N) | 無変更 |
| `createBook({ columns: { width: '20em' } })` (段幅宣言) | 無変更 |
| `addObstacle(page, { at: { col, row } })` (legacy 物理 row) | 無変更 (whenColumns 未指定時の経路) |
| `addObstacle(book, { whenColumns })` (新) | 追加。 第 1 引数 overload で book を受け取る |

ColumnsConfig Union 拡張は型レベルで後方互換 (既存の `number` / `{ width }` を含む 3 モード Union)。 既存 demo / E2E は本 PR で書き換えない (Sprint 2 で新 demo / 新 E2E を別途追加、 Sprint 5 で demo 切り替え)。

## 評価軸 6 項目 self-check

`plans/2026-05-14_v0.4-evaluation-criteria.md` の 6 項目について、本 API がどう満たしているか・検証手段が何かを 1 項目ずつ事実ベースで記録する。各項目に検証コマンド (grep / pnpm test / pnpm exec playwright) を併記し、 LLM の自己申告ではなく独立 evaluator が再現できる形にする。

### #1 text は 1 本の連続ストリーム、 page は可変、 resize で再分配

本 API は flow engine の `addFlow(book, { text })` 経路に手を加えず、 obstacle の variant resolve のみを reflow cycle に追加した。 obstacle が N 変化で `display: none` / 再 attach される際も `_sourceText` は単一の string のまま保持され、 distribute が page を必要数に増減させる。

検証:
- `e2e/basic.spec.ts` の `book 全体の visible text が source と厳密一致` で `V === SOURCE_TEXT` を完全一致 assertion (`expect(V).toBe(SOURCE_TEXT)` + `expect(V.length).toBe(SOURCE_TEXT.length)`)
- `e2e/columns-variant.spec.ts` の `visible text V === SOURCE_TEXT (N=...)` で 4 viewport (320/640/1024/1440) 全てで `stripNewlines(V) === stripNewlines(SOURCE_TEXT)` 完全一致
- `e2e/flow-engine-resize.spec.ts` 5 ケースで resize 前後の文字列一致を assert
- コマンド: `pnpm exec playwright test e2e/basic.spec.ts e2e/columns-variant.spec.ts e2e/flow-engine-resize.spec.ts`

### #2 横書きも縦書きも同じ flow engine、 duplicate 設計は両方捨てる

writing-mode による分岐は `src/flow/axis.ts` の `axisProjection` に集約され、 distribute / measure / reflow は projection 経由で軸を扱う。 本 API で追加された `--tilepage-line-height` も axis-agnostic な CSS 変数で表現され、 縦書き拡張時にも同じ projection で再利用できる。

検証:
- `grep -rnE "writing-mode|vertical-rl|horizontal-tb" src/ --include='*.ts'` で条件分岐 hit が `src/flow/axis.ts` の projection 本体に集中していること (TilePage.ts では vertical-rl + supportedColumns の早期 throw 1 箇所、 inlineSizeOfElement の幅取得 1 箇所、 deriveColumnsFromSupported の inline-size 取得 1 箇所のみ)
- `e2e/flow-engine.spec.ts` の `horizontal-tb` / `vertical-rl` 両ケース GREEN
- `e2e/v0.4-axis-selfcheck.spec.ts` の axis projection 整合テスト 7 ケース GREEN
- コマンド: `pnpm exec playwright test e2e/flow-engine.spec.ts e2e/v0.4-axis-selfcheck.spec.ts`

### #3 段数は N (configurable)、 6 はデフォルト値に過ぎない

`ColumnsConfig` は 3 形式の N 指定を受け付ける排他的 Union:
- fixed N: `columns: 6` (number リテラル)
- auto-fit width: `columns: { width: '14em' }` (段幅から N を実数導出)
- discrete supported: `columns: { supported: [2,4,6,8], breakpoints: { 8:'90em', 6:'60em', 4:'40em', 2:'0' } }` (著者が許可した N の集合に離散スナップ)

著者が定義していない N は `whenColumns` の variant 解決時に graceful degradation で `display: none`。 デフォルト N=6 はあくまで `options.columns ?? 6` の fallback 値で、 著者が自由に N を選べる。

検証:
- `e2e/columns-variant.spec.ts` で viewport 320 → N=2、 640 → N=4、 1024 → N=6、 1440 → N=8 の 4 ケースが GREEN (`data-active-columns` 属性で実値を assert)
- `e2e/basic.spec.ts` の `book root has data-active-columns="6"` で viewport=1024 → N=6 の離散スナップを実証
- 既存 vitest の `flow-engine.spec.ts` で N=2/3/6/8 (fixed) が GREEN 維持
- king variant @ N=6 の意図的省略により graceful degrade が DOM 不在 / `display: none` のどちらかで観測可能 (`e2e/basic.spec.ts` の `graceful degrade` ケース、 `e2e/columns-variant.spec.ts` の N=6 ケース)
- コマンド: `pnpm exec playwright test e2e/columns-variant.spec.ts e2e/basic.spec.ts`

### #4 px 固定なし、 論理プロパティ + 1fr / % で軸抽象化

公開 API / アプリケーション側 CSS / ロジックコードのいずれにも px リテラル (`14px`) / テンプレートリテラル `${n}px` は存在しない。 obstacle 配置の y 座標は `--tilepage-line-height` CSS 変数経由で行高単位に表現され、 `calc(var(--tilepage-line-height, 1.5) * 1px)` で単位化される。 単位文字列 `px` の string concatenation は src 配下に 0 件。

検証:
- 静的: `grep -nE "[0-9]+px" src/flow/*.ts src/TilePage.ts` が 0 hit (exit 1)
- 静的: `grep -nE "\$\{[^}]+\}px" src/flow/*.ts src/TilePage.ts` が 0 hit (exit 1)
- 静的: `grep -nE "--tilepage-line-height|var\(--tilepage" src/` で CSS 変数経由の使用箇所が hit (set + use の両方向で複数 hit)
- 設計: `src/TilePage.ts` の `syncLineHeightVar` で root に `setProperty('--tilepage-line-height', String(lh))` を **単位なし数値** で書き出し、 `src/styles/tilepage.css` で `calc(var(--tilepage-line-height, 1.5) * 1px)` により px 化 (px 化責務は CSS 側のみ)

### #5 検証は visible text 文字数照合 (DOM 存在ベースは不可)

E2E の本文一致 assertion は全て `visibleTextOf(page, { rootSelector }).text` をソースとし、 DOM ノードの存在数 / class 名 / 子要素数ではなく **実際に画面で読める文字列** を SOURCE_TEXT と完全一致照合する。 `display: none` の要素は visible text に含まれず、 graceful degrade した obstacle が visible text の判定を曇らせない。

検証:
- `e2e/basic.spec.ts` の `book 全体の visible text が source と厳密一致` で `expect(V).toBe(SOURCE_TEXT)` と `expect(V.length).toBe(SOURCE_TEXT.length)` を両方 assert
- `e2e/columns-variant.spec.ts` の 4 viewport で `stripNewlines(V) === stripNewlines(SOURCE_TEXT)` を完全一致 assert (改行は visibleTextOf の rect 境界の rendering detail を吸収するための strip、 本文 character 数は 9839/9839 で完全一致)
- helper: `e2e/helpers/visibleText.ts` (DOM Range + getClientRects ベースで実描画文字列を抽出)
- コマンド: `pnpm exec playwright test e2e/basic.spec.ts e2e/columns-variant.spec.ts -g "visible text"`

### #6 CSS でできないところは JS で測って切る

CSS のみで決まらない 3 つの量を JS で実測して reflow cycle に乗せている:
1. **inline-size** (page の段組み inline 軸サイズ): `inlineSizeOfElement` が `getBoundingClientRect` ベースで実測し、 N 解決の入力にする
2. **line-height** (1 行の block 軸ピッチ): `src/flow/measure.ts` の `measureLineHeight` が Range#getClientRects → computed style → probe element の 3 段フォールバックで実測。 各段で `Number.isFinite && > 0` ガード付き
3. **breakpoint 閾値**: CSS 長さリテラル (`'40em'` 等) を `resolveCssLengthToPx` が一時要素 + `getBoundingClientRect` で px 化し、 inline-size との比較に使う

実測値はいずれも CSS 変数 (`--tilepage-line-height`) または内部数値として保持され、 公開 API / アプリケーション側 CSS には漏れない (評価軸 #4 と整合)。

検証:
- 実装存在: `grep -nE "measureLineHeight|Number\.isFinite" src/flow/measure.ts` で関数本体と 0/NaN ガードが hit
- 適用経路: `grep -nE "setProperty\('--tilepage-line-height'|--tilepage-line-height" src/` で CSS 変数 set と use が 2 件以上 hit
- 動作: `e2e/columns-variant.spec.ts` の `gridColumnStart` / `gridRowStart` 完全一致 assert が GREEN (variant の at.line が実 grid 行に反映されるためには line-height 実測が成立している必要がある)
- コマンド: `pnpm exec playwright test e2e/columns-variant.spec.ts`

# v0.5 Semantic Obstacles 設計書

tilepage v0.5 で導入する「画像以外の意味的矩形要素」 (Headline / Pullquote / Box) と、 `addFlow` への段落スタイル拡張 (`paragraph` オプション) の仕様。 vertical-rl 対応は PR B で別途扱い、 本書は PR A の範囲 (horizontal-tb のみ) に閉じる。

前提:

- `docs/design/v0.4-flow-engine.md` の flow engine 仕様
- `docs/design/v0.4-columns-variant.md` の `whenColumns` variant API

本書のスコープは「**矩形は表示物、 Flow は注入物**」 の線引きを守りつつ、 既存 `addObstacleHorizontal` の薄いラッパーとして 3 種の意味的要素を追加することと、 `addFlow` に CSS パススルーの段落整形オプションを足すことの 2 点。 flow engine 本体 (`src/flow/`) には触らない。

---

## ゴール

1. 新規公開 API として以下 3 関数を追加する:
   - `addHeadlineHorizontal(book, options)`
   - `addPullquoteHorizontal(book, options)`
   - `addBoxHorizontal(book, options)`
2. 既存 `addFlow(book, options)` に `options.paragraph` を足し、 字下げ / 両端揃え / 禁則 / hanging-punctuation を CSS パススルーで適用する
3. 上記すべてを `src/obstacles/` 配下にファイル分割し、 `src/TilePage.ts` 61.8 KB のさらなる肥大化を避ける
4. Rule (罫線) は v0.5 では追加せず、 Book 側の grid-gap + 将来の `rule: boolean` 案に委ねる
5. 既存 E2E (`basic.spec.ts` / `columns-variant.spec.ts` / `vertical-meros.spec.ts` / `flow-engine*.spec.ts`) と既存 demo (`demo/main.ts` / `demo/vertical-meros/`) は無傷に保つ

非機能:

- ゼロ依存を維持する (`.claude/rules/components.md` 準拠)
- バンドルサイズ目標 (v1.0 で 10-15 KB) に向け、 共通 helper を抽出する
- 段落スタイルは flow engine 内部 (`src/flow/chunk.ts` / `distribute.ts` / `measure.ts` / `reflow.ts` / `axis.ts`) には貫通させず、 `addFlow` 呼び出し点で受けて DOM の data 属性に変換する

## API シグネチャ

### 共通の継承元

`src/TilePage.ts` 122 行の `BaseObstacleOptions` と 131 行の `HorizontalObstacleOptions` を継承する。 これにより `shape` / `shapeMargin` / `syncClipPath` / `whenColumns` 等の既存仕様がそのまま使える。

```ts
// 既存 (src/TilePage.ts より引用)
export interface BaseObstacleOptions {
  shape?: ObstacleShape;
  src?: string;
  alt?: string;
  element?: HTMLElement;
  shapeMargin?: string;
  syncClipPath?: boolean;
}

export interface HorizontalObstacleOptions extends BaseObstacleOptions {
  whenColumns: Partial<Record<number, HorizontalWhenColumnsVariant>>;
}
```

新規 3 関数は **すべて `whenColumns` を必須継承** する。 ロードマップ原文の `at` プロパティは v0.4 で `whenColumns[N].at` に内包済みで、 `addObstacleHorizontal` 同様 legacy `at` は禁止する (`src/TilePage.ts` 449 行で throw)。

### addHeadlineHorizontal

```ts
// src/obstacles/headline.ts
export interface HeadlineHorizontalOptions
  extends Omit<HorizontalObstacleOptions, 'element' | 'src' | 'alt'> {
  // 1-6 整数。 内部で <h${level}> を生成する。 範囲外は throw。
  level: 1 | 2 | 3 | 4 | 5 | 6;
  // 見出しテキスト。 改行は <br> に変換せず、 そのまま textContent に流す
  // (改行を入れたければ呼び出し側で element 経路を使う想定だが、
  //  Headline では element 経路を閉じるため、 text 単独入力に絞る)。
  text: string;
  // 枠 bbox に収まる最大 font-size を二分探索で決定する。 default false。
  // true 時は font 計測のため呼び出し側で document.fonts.ready を待つ前提
  // (実装側でも await して二重安全にする)。
  fitToBox?: boolean;
}

export function addHeadlineHorizontal(
  book: Book,
  options: HeadlineHorizontalOptions,
): Obstacle;
```

判断根拠:

- `element` / `src` / `alt` を `Omit` で外す理由: Headline は `<h${level}>` を内部生成するため、 呼び出し側で element を渡す穴を空けると意味的構造が壊れる
- `level` を `1 | 2 | 3 | 4 | 5 | 6` リテラル union にする理由: TypeScript の型レベルで範囲外を弾けるため。 runtime 検証も併用 (string 化された数値リテラルが流れ込んだ場合の guard)
- `fitToBox` 既定値が `false` の理由: 二分探索は font 計測 cost と flaky リスクを伴うので、 明示 opt-in にする

### addPullquoteHorizontal

```ts
// src/obstacles/pullquote.ts
export interface PullquoteHorizontalOptions
  extends Omit<HorizontalObstacleOptions, 'element' | 'src' | 'alt'> {
  // 引用本文。 plain text。 引用符 (「 」) は CSS quotes プロパティで出すため、
  // 呼び出し側で text に「 」 を含めない。
  text: string;
  // 引用元。 undefined の時は <cite> を生成しない。 plain text のみ。
  cite?: string;
}

export function addPullquoteHorizontal(
  book: Book,
  options: PullquoteHorizontalOptions,
): Obstacle;
```

判断根拠:

- 内部で `<blockquote>` を生成し、 `cite` 指定時のみ `<cite>` 子要素を追加する
- 引用符を文字列に含めない理由: writing-mode 切替 (PR B) で `quotes` 値を変える時に DOM を書き換えずに済む。 CSS のみで対応可能になる
- `cite` URL 属性 (`<blockquote cite="https://...">`) はこの版では未対応 (v0.6 以降の検討事項)

### addBoxHorizontal

```ts
// src/obstacles/box.ts
export interface BoxHorizontalOptions
  extends Omit<HorizontalObstacleOptions, 'src' | 'alt'> {
  // 箱の中身。 呼び出し側で任意 HTMLElement を渡す (静的コンテナとして振る舞う)。
  // element 省略時は空の <div> を生成 (枠線のみの箱として使えるように)。
  element?: HTMLElement;
  // CSS border 値 (例: '1px solid #000')。 inline style としてパススルー。
  border?: string;
  // CSS padding 値 (例: '1em' / '0.5em 1em')。 inline style としてパススルー。
  padding?: string;
}

export function addBoxHorizontal(book: Book, options: BoxHorizontalOptions): Obstacle;
```

判断根拠:

- `element` を残す理由: Box は「呼び出し側で組み立てた DOM を流し込む箱」 という位置づけ。 Headline / Pullquote と非対称になるが、 これは Box の責務の差 (= 静的コンテナ提供) を反映している
- `src` / `alt` を `Omit` で外す理由: 画像 obstacle は `addObstacleHorizontal` の責務。 Box が `<img>` を作ってしまうと API の意図が曖昧になる
- `border` / `padding` を `inline style` に直接適用する理由: data 属性経由で CSS セレクタに渡すと「任意の CSS 値」 を表現できない (`'1px solid #000'` 等は CSS attribute selector では受けられない)。 inline style に直接書く方が透過パススルーの責務に忠実

### addFlow の paragraph 拡張

```ts
// src/TilePage.ts の FlowOptions に追加
export type ParagraphKinsoku = 'strict' | 'normal' | 'none';

export interface ParagraphOptions {
  // CSS text-indent パススルー。 '1em' / '0' 等の CSS 長さリテラル。
  // 単段一律適用 (column 全体に text-indent を当てる)。 <p> 分割は v0.5 では行わない。
  indent?: string;
  // text-align: justify を column に当てる。 last-line は text-align-last: auto 固定。
  justify?: boolean;
  // line-break + word-break の組み合わせ。 'none' は line-break: anywhere。
  kinsoku?: ParagraphKinsoku;
  // hanging-punctuation: allow-end を column に当てる。
  hangingPunctuation?: boolean;
}

export interface FlowOptions {
  text?: string;
  paragraph?: ParagraphOptions;
}
```

判断根拠:

- `paragraph` を optional にする理由: 既存呼び出しの後方互換を完全に保つため
- 値型を string / boolean / 列挙の混在にする理由: CSS プロパティ側の表現力に合わせる (`indent` は CSS 長さリテラル、 `kinsoku` は 3 値列挙、 `justify` / `hangingPunctuation` は二値)
- `paragraph` を flow engine に貫通させない理由: chunk / distribute / measure / reflow / axis は writing-mode と char index しか見ない設計を v0.4 で固めた。 段落整形は CSS で完結可能で、 JS 側に状態を持つ必要がない

## Rule の採否判断

### 結論: v0.5 では Rule を採用しない (= 不採用)

ロードマップで第 1 候補だった `addRuleHorizontal` は v0.5 から外し、 Book 側 grid-gap + 将来の `rule: boolean` 案に委ねる。 sprint 数を 6 に抑える狙いもある。 v0.6 以降で要望が出た時点で再検討する。

### 判断根拠

`src/styles/tilepage.css` を読み、 段境界の補助線として既存の何が使えるかを評価した:

- L26: `.tilepage-obstacle-layer` で `column-gap: var(--tilepage-gutter, 1em);`
- L46-47: `.tilepage-flow-layer` で `grid-template-columns: repeat(var(--tilepage-columns, 6), 1fr); column-gap: var(--tilepage-gutter, 1em);`
- L60-63: vertical-rl で `column-gap: var(--tilepage-gutter); row-gap: 0;`

`--tilepage-gutter` は既に CSS 変数として exposed されており、 呼び出し側が `createBook({ gutter: '1.5em' })` で調整できる (`src/TilePage.ts` 197 行参照)。 段境界の補助線は、 grid-gap の中央に `::before` で 1px の縦罫線を出す CSS パターンで 9 割方の用途を満たせる。 これは Book 側 CSS の拡張 (`rule: boolean` の prop に集約) で済む話で、 obstacle として領域を消費する `addRuleHorizontal` を別途用意する積極理由が薄い。

横段の補助線 (記事間の区切り罫線) も、 `addObstacleHorizontal` に `element` として border-only `<div>` を渡せば現状で再現可能。 専用 API を切らなくても運用できる。

### 採用する場合 (= sprint 5.5 を追加するケース)

sprint 1 の実機検証で「段境界の罫線が grid-gap + CSS では足りない」 と判明した場合、 sprint 5.5 として以下を追加する:

- `addRuleHorizontal(book, { whenColumns, direction: 'vertical' | 'horizontal', weight, ... })` を `src/obstacles/rule.ts` に実装
- 内部で薄い `<div>` (border のみ) を作って `addObstacleHorizontal` の element 経路に流す
- `direction` は **罫線自体の向き** (vertical = 縦罫線 = 段境界、 horizontal = 横罫線 = 記事区切り)
- `weight` は CSS border-width パススルー

本書時点での結論は「不採用」。 sprint 数は 6 のまま。 evaluator に対しては sprint 5.5 を追加する **必要なし** をフラグで申告する (`rule_sprint_5_5_needed: false`)。

## CSS 設計 (data 属性ベース)

### 新規 class

`src/styles/tilepage.css` に追記する class:

```css
/* 見出し: margin リセット + line-height 圧縮で枠内に収まりやすくする */
.tilepage-headline {
  margin: 0;
  line-height: 1.2;
}

/* 引用: <blockquote> の margin リセット + quotes プロパティで引用符を出す */
.tilepage-pullquote {
  margin: 0;
  quotes: '\201C' '\201D' '\2018' '\2019';
}
.tilepage-pullquote::before {
  content: open-quote;
}
.tilepage-pullquote::after {
  content: close-quote;
}
.tilepage-pullquote cite {
  display: block;
  font-style: italic;
}

/* 囲み記事: 既定スタイルなし。 border / padding は呼び出し側 inline style から流れる */
.tilepage-box {
  box-sizing: border-box;
}
```

### writing-mode 別の quotes 値

PR A では `horizontal-tb` の左二重引用符 / 右二重引用符 (`\201C` / `\201D`) を既定とする。 vertical-rl 用の `「 」` (`\300C` / `\300D`) は PR B sprint-3 で `.tilepage-page[data-writing-mode="vertical-rl"] .tilepage-pullquote` セレクタ経由で上書きする。 PR A の CSS には書かない (PR B のスコープ)。

### 段落用 data 属性セレクタ

`addFlow` で `paragraph` オプションを受けた時、 各 column 要素 (`.tilepage-column`) または `.tilepage-flow-text` に data 属性を付与する。 CSS 側はその data 属性に対するセレクタで段落整形を当てる:

```css
.tilepage-flow-text[data-paragraph-indent] {
  text-indent: var(--tilepage-paragraph-indent);
}
.tilepage-flow-text[data-paragraph-justify="true"] {
  text-align: justify;
  text-align-last: auto;
}
.tilepage-flow-text[data-paragraph-kinsoku="strict"] {
  line-break: strict;
  word-break: normal;
}
.tilepage-flow-text[data-paragraph-kinsoku="normal"] {
  line-break: normal;
}
.tilepage-flow-text[data-paragraph-kinsoku="none"] {
  line-break: anywhere;
}
.tilepage-flow-text[data-paragraph-hanging-punctuation="true"] {
  hanging-punctuation: allow-end;
}
```

`indent` のみ CSS 変数経由にする理由: data 属性値は「任意 CSS 長さリテラル」 を取りうるため、 セレクタ側で固定値を書けない。 JS 側で `el.style.setProperty('--tilepage-paragraph-indent', options.indent)` で流し込み、 セレクタは `var(...)` 参照だけにする。 `data-paragraph-indent` 属性は「指定されているか」 の boolean 用途で attribute presence selector (`[data-paragraph-indent]`) を駆動する。

`justify` / `kinsoku` / `hangingPunctuation` は属性値で出し分けるため、 CSS 変数は使わず attribute value selector で完結する。

| `justify` 未指定 | (data 属性なし) | 同上 |

### 適用先の選択

data 属性は各 `.tilepage-flow-text` 要素に付ける (= column 内の本文ラッパー)。 `.tilepage-column` ではなく `.tilepage-flow-text` を選ぶ理由は、 `text-indent` / `text-align` の継承が「テキストブロック」 単位の方が直感的なため。 ただし `text-indent` は inline 要素には継承しないので、 `.tilepage-flow-text` が block 要素であることを CSS 側で保証する (`src/styles/tilepage.css` L73 で既に inline-size: 100% を持つが、 block 表示は default なのでそのままで動く)。

### 段落 `indent` の単段一律適用方針

現 flow engine (`src/flow/chunk.ts`) は char (grapheme) 単位で chunk するため、 「段落」 という概念を持たない。 `\n\n` を `<p>` に変換するパース層は現状なく、 v0.5 で導入するとフレーム連結 (v2.0) と同等の作業になる。

**v0.5 での割り切り**: column 全体に `text-indent` を一律適用する。 つまり「各 column の先頭文字が字下げされる」 形になる。 段落区切りごとの字下げ (本来の段落 indent の意味) は v0.5 では実現しない。

この割り切りを設計書に明記しておく理由は、 利用者が「段落区切りで字下げが効かない」 と気付いた時に「v0.5 の仕様」 として理解できるようにするため。 sprint-5 の E2E でも「column 先頭の text-indent が effective である」 ことを assert する (= 段落区切り字下げは assert しない)。

`<p>` 分割対応は v2.0 のフレーム連結 (= Box の中に Flow を流す機構) と同じ作業範囲なので、 そちらに統合する。

### 段落 `justify` の last-line 固定

`text-align-last` はブラウザ間で実装差が大きい (特に Chrome / Safari / Firefox)。 `text-align-last: auto` に固定して、 ユーザー設定不可とする。 `text-align: justify` の last-line は各ブラウザ既定挙動 (大抵 `start` 揃え) に任せる。

理由:

- `text-align-last: justify` を当てると最終行も両端揃えになり、 文字間隔が広がりすぎて可読性が落ちる
- last-line の挙動を可変にすると E2E の computed style assert がブラウザ差で揺れる (Playwright は Chromium のみだが、 将来の対応 browser を増やす時に問題が顕在化する)
- `text-align-last` を制御したい利用者は CSS を直接書ける (本機能は薄い CSS パススルーなので、 詳細制御は CSS 直書きを推奨)

設定可能化は v0.6 以降の検討事項。 PR A の `ParagraphOptions` に `textAlignLast` を入れない。

### 判断根拠

`src/TilePage.ts` の規模:

- ファイルサイズ: 61.8 KB
- 関数 / 型の数: `export interface` / `export type` / `export function` / `export const` の grep で 26 件 (うち TilePage.ts 内のものが 19 件)

- 内部関数 10-15 個 (normalize / addObstacleToBook / resolveVariants / etc)
- 公開型 6 個 (`BaseObstacleOptions` / `HorizontalObstacleOptions` / `VerticalObstacleOptions` / `Obstacle` / `HorizontalWhenColumnsVariant` / `VerticalWhenColumnsVariant`)
- 内部型 1 個 (`ObstacleOptions`)
- 内部 helper export 1 個 (`_internalAspect`)

これらは互いに局所的に閉じており、 `src/TilePage.ts` 残留組 (`createBook` / `addPage` / `addFlow` / `runDistribute` 等) との依存は `addObstacleToBook` が `book._variantObstacles` / `triggerRedistribute` を呼ぶ点と、 `resolveVariantsForBook` が `book.pages` / `book.columns` を読む点に限られる。 これらは Book 内部状態への参照だけで、 関数呼び出しの一方向依存。 機械的なファイル移動 + import path 整理で完結する見込み。

物理分割を先行 PR にする積極理由 (レビュー容易性、 巨大 PR 回避) はあるが、 以下の消極理由で PR A 内に閉じる:

1. sprint-2 単体は機能変更ゼロのコミットで、 既存 E2E が GREEN であれば diff は機械的にレビューできる。 1 PR 内で sprint-2 → sprint-3 と進めても、 commit を分ければレビュー粒度は確保される
2. 先行 PR を切ると、 ローカル mater main の進行と PR A の rebase が二重に発生する。 個人開発の運用ではコストが見合わない
3. PR A 全体の sprint 数は 6。 1 PR でマージ可能な規模感 (v0.4 flow-engine PR と同等以下)

### 例外条項

sprint-2 完了時点で `src/TilePage.ts` の diff が予想を超えて巨大化した場合 (例: 行数 +500 行以上の追加 / 削除が発生)、 sprint-2 を独立 PR に切り出す判断を保留する。 evaluator が sprint-2 評価時に diff サイズを確認し、 適宜 implementer に再分割を依頼できるようにする。
